# 参照画像から、動いて小道具を持てる3Dキャラクターへ

構成・会話台本 v1／2026-10-14。目安は約6〜8分。音声は未生成・尺は未実測であり、下記の章配分は編集の目安にすぎない。固定秒数・フレームのタイムラインはまだ作らない。

今回の成果はこの構成・台本まで。音声、立ち絵の追加差分、教材の画像・3D・動画、Remotion実装、公開用説明欄は未制作。使用モデル・料金・サービス仕様の最新調査も未実施のため、料金案内や操作手順の網羅を目的にしない。

## 企画と教材

対象は、CodexやClaude CodeでWebサイト・小さなアプリを作ったことはあるが、3Dの制作工程には詳しくない人。「画像を3D生成へ送る」から「動かして持たせる」までに、何を確認して直すのかを伝える。

制作で得た知見だけを一般化する。特定用途のブランチにある人物・名前・服のロゴ・小道具の固有表記・GLB・PNG・完成動画は使わず、mainへコピーしない。教材は今後、次の仕様で新規作成する。

- 顔の特徴を持たない無地の人型マネキン。グレーのパーカーを着用し、下ろしたフードの厚みが見える。既存人物の髪型・顔・体型を再現しない。
- 黒いボディーと明るい長筒レンズからなる汎用望遠カメラ。メーカー名・型番・ロゴを付けない。既存の生成モデルは流用しない。
- 文字の説明には別紙の「SAMPLE TEXT」を使う。文字はコードまたは通常の組版で正確に描き、必要なら教材のパーカーへ後付けする。
- 失敗例は教材用の模式図として新規作成し、画面へ「仕組みを説明する模式図」と表示する。実際の過去出力や新しい生成結果だと見せかけない。

## 会話台本

各シーンの画面指示は制作案。画像・映像はまだ存在しない。発話IDは改稿や音声生成の対応付けに使い、時間を表さない。

### S01　画像を、使えるキャラクターへ

画面案：BGMを薄く先行。無地のマネキンが歩き、汎用カメラを装備し、右手で肩の横へ持ち上げて左手を腰へ置く新規デモを無音で見せる予定。冒頭デモの制作・検証が終わるまでは完成例として扱わない。工程図は「参照 → 3D生成 → 仕上げ → リグ → 装備 → 確認」の順で発話に合わせて出す。

- S01-01 やめ太郎「画像から3Dにするだけやと思ってたら、歩いてカメラまで持っとる。ここまで一発でできるん？」
- S01-02 たこさん「今回は、いくつかの工程に分ける方法です。形を作り、曲がり方を整えて、最後に小道具を持たせます。」
- S01-03 やめ太郎「どうも、やめ太郎やで。ワイ、3Dは見る専門やったわ。」
- S01-04 たこさん「たこさんです。今日は、生成ボタンの前後で何をするのか。実際の制作から得た工夫を、教材で説明します。」

### S05　見た目が近くても、寸法と文字を確認

- S05-01 やめ太郎「生成されたカメラ、ぱっと見はそれっぽいな。」

- S05-04 たこさん「だから、部位を分けて比率を直します。文字も読めるか確認し、必要なら正確な文字を別の薄い面などで載せます。」
- S05-05 たこさん「元の生成データは残して、どの範囲をどう直したかを記録します。正確な製品の設計データになった、という意味ではありません。」

- S06-03 やめ太郎「骨の位置が合ってたら、服も勝手にきれいに曲がるんちゃうの？」
- S06-04 たこさん「そこは別の調整です。肘を曲げたら袖がつぶれる、頭を向けたら背中のフードまで付いてくる、といったことがあります。」
- S06-05 やめ太郎「フードにまで首を振られたら、落ち着かへんな。」
- S06-06 たこさん「肩を上げる、肘を曲げる、首を向ける。実際の動作で見て直します。既存の動きを使う場合は、骨の対応や基準姿勢も合わせます。」
- S06-07 やめ太郎「止まってるときに似てるかと、動かして自然か。両方見るんやな。」

### S07　持たせる位置と、握る指

画面案：手側の取付点とカメラ側の握る位置を点で表示し、向きと単位を合わせて重ねる。次に右手の指だけを色付け。「元の動作 → 装備中だけ指の握りを重ねる → 解除して元の動作へ」の順で強調。右肩のカメラと左腰の手を別視点で示す予定。

## 後工程への引き渡し

### 先に確定・制作するもの

1. この構成と配役を必要に応じて改稿する。目安の尺より説明の理解しやすさを優先する。
2. 無地マネキンと汎用カメラ、参照シート、文字別紙、骨・ウェイト・取付点の図、失敗を説明する模式図を新規制作する。すべて未生成。教材の「正常例」も制作後に検証してから採用する。
3. 冒頭の装備デモ、各寄り画面、ON/OFF・動作切替・時間移動のデモを教材で制作する。既存の限定用途モデル・動画を複製、変名、部分切り抜きして代用しない。
4. 教材素材IDと各発話IDの対応表を作り、未制作の素材を実在パスであるかのようにmanifestへ登録しない。模式図と実行結果を区別する。

### 音声・編集

- 原稿、音声用の読み、字幕改行は分ける。読み候補：Wan＝ワン、Imagegen＝イメージジェン、Tripo＝トリポ、Three.js＝スリージェイエス、Remotion＝リモーション、3D＝スリーディー。採用前に読みと聴感を確認する。
- 音声生成後に各発話の実測尺、無音、会話の間を確認し、章の尺・字幕・強調位置・デモの長さを決める。この原稿の配分や既存テンプレートの固定フレームをそのまま正本にしない。
- BGMは会話を妨げない薄い音量。既存作品の曲を自動採用せず、使用素材・利用条件・クレジットを選曲時に記録する。会話後に音量を持ち上げない。
- 技術解説の採用v12から必要な画面コードだけ抽出する。章名、話者ID、字幕色、立ち絵、台詞からの資料判定を新作へ合わせ、旧台詞・音声・価格・動画・manifestを丸ごとコピーしない。
- 動画化の際は`remotion-video`へ引き渡す。完成出力は通常の横16:9・1280×720・30fpsを候補とするが、素材生成の解像度と混同しない。この段階では音声・素材・動画を生成していない。

### 検証と記録

- 本文の「8秒」「半周」「描画破損」は制作記録から得た事例で、推奨設定や成功率ではない。現在の料金を紹介する場合はその時点で別途確認し、過去の単発費用を一般価格にしない。
- S03の補完側面は推定だと字幕と資料の両方で分かるようにする。図が正投影に見えても、生成画像の整合性が保証されたとの説明にしない。
- 新規教材で見せた機能、変形、接触、画角をそれぞれ確認し、未検証の動作へ合格範囲を広げない。簡易ストラップを追加する場合は布の物理挙動と区別する。
- 最終MP4の全編デコードに加え、各レイアウト、動作、寄り、切替前後、末尾を実フレームで確認する。既知の異常に応じた全フレーム検査も併用する。静止画の成功だけで完成動画を合格にしない。
- 720p実寸で字幕・図のラベル・強調の順序、表情切替、口パク、読みと会話の間、BGMを確認する。機械検査と聴感・目視の実施範囲を分けて記録する。
