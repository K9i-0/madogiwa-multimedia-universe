# 技術解説のAI向け資料

2026-10-22ユーザー指定。技術解説では「技術を実行する指示書」と「動画内容の記録」を分ける。主操作は「AIへの指示をコピー」1つ。依頼文と実行指示書全文をコピーし、動画資料から実行指示書へリンクする。ネタ系解説には一律適用しない。台本相談だけの依頼を制作・公開へ拡張しない。

## 2つの正本

- **実行指示書（workflow.md）**：視聴者の素材・環境で制作を進めるための指示。要約や計画の提示だけで完了させない。新しい制作で使う技術・ツールの条件を維持管理する。
- **動画資料（guide.md）**：採用台本の要点、発話、画面内プロンプト、当時の設定・料金、補足と出典。冒頭に実行指示書への絶対URLを置く。実発話や過去の生成条件を現行仕様へ書き換えない。

資料には更新日と相互リンクを付け、動画資料にはYouTube URL、制作ページ、対象版・制作日も記す。台本由来の発話を自動書き起こしと称さない。依頼例や補足の追記は動画内の発言と区別する。

## 実行指示書の作成

台本の要約だけで作らず、実際に採用した入力・生成設定・組立や編集コード・失敗と修正記録を確認する。内部スキルや制作メモを丸ごと公開せず、外部の利用者に必要な指示を編集する。

1. **目的と成果物**：ユーザーの入力・用途・完成条件を示す。3Dプリントなど依頼にない用途や成果物を勝手に追加させない。
2. **環境確認**：工程ごとに利用するツールと実際の対応機能を確認させる。ローカルGPU、言語モデル、画像モデル、動画モデルを区別する。実行機能がない場合は設定や素材提供での再開方法を示す。APIキーを会話へ貼らせない。
3. **必須と代替**：工程ごとに何が必須で何を代替できるか、品質・機能の条件を明記する。Tripo回のTripo生成は必須。回転動画は条件を満たす別モデルを使える。動画制作回のモデルは未指定なら選べるが、ユーザーが特定モデルでの再現を指定した場合は維持する。LINE回は連続原画とAPNGが核で、画像生成器のブランドやPets登録は必須ではない。
4. **不足時の動作**：必須工程は止め、不足・再開方法を具体的に伝える。独立した準備は進めてよい。簡易モデリング、静止画スライド、GIF等を別方式の完成品として独断で代納しない。方式の変更はユーザーが選んだ場合だけ行う。
5. **参照資料**：公開リポジトリの具体的なファイルURL、読む順番と目的を書く。コードの依存ファイル・設定・入力への辿り方も示す。相対リンクの解決基準とraw取得方法を記す。未取得の内容を推測して実行させない。個別キャラの座標・素材・修正率・フォント・料金等を汎用の既定値として複製しない。
6. **工程と判定**：各工程の入力・作業・出力・合格条件、失敗時にどの工程へ戻るかを示す。生成・レンダー・形式検査の成功と見た目・音声・動作の品質を区別する。最終書き出しファイルを確認させる。
7. **記録と納品**：成果物、再現に必要な入力・コード・設定、確認済み事項と未解決事項を記録する。既存の許可範囲を尊重し、未指定の課金・追加購入や外部投稿を自動で行わせない。

現在の公式仕様と動画当時の実績・試算を区別する。参照画像・API設定・有料枠まで資料で提供されると説明しない。生成品質や審査通過を保証しない。

## 既存実装へ追加する

パスは `16_MADOGIWA_STUDIO/` 基準。

- 動画資料：`src/content/explainers/<slug>.md`
- 実行指示書：`src/content/workflows/<topic>.md`
- 対象slugと採用YouTube ID：`src/lib/explainer-catalog.ts`
- 両Markdownの登録：`src/server/explainer-guides.ts` の `markdown` と `workflow`
- 制作ページ：`https://madogiwa.work/episodes/<slug>`
- 実行指示書：`https://madogiwa.work/episodes/<slug>/workflow.md`
- 動画資料：`https://madogiwa.work/episodes/<slug>/guide.md`

共通UIのコピー文を特定題材専用にしない。台本を実行指示のコピーへ混ぜない。サイトの資料表示はリッチなMarkdownレンダーを使わず、等幅の読み取り専用テキスト欄でMarkdown原文を見せる。各欄に同じ本文をコピーするボタンを添える。主操作は1つのまま、詳細欄のコピーは原文確認用とする。既存URLを維持し、4つのコピー方法へ戻さない。未整備の回は実行指示書があると装わず、相談用資料と表示する。新規の技術解説では両資料を揃える。

両資料は対応する公開動画に紐付け、制作ノートの公開とは独立させる。公開のために非公開ノートを有効化しない。初期HTMLに本文を含め、Markdown URLは認証・JavaScript不要のtext/markdownを返す。動画差し替え時は内容と対象版を確認してIDを更新する。

## 公開前後の確認

- 未公開・別ID・未登録・アーカイブ時は両Markdownが取得できないことを確認する。
- 正しい公開動画では両資料を取得でき、本文が正本と一致すること、資料間のリンクとGitHubの必読ファイルが取得できることを確認する。HTTP取得と各AIの閲覧対応は区別する。
- コピーが依頼文とその回の実行指示書全文になっていること、台本や別題材の依頼が混入しないことを確認する。拒否時の手動コピー欄を維持する。スマホ表示も確認する。
- 資料だけを読む新規利用者の視点で、(a)必須ツールなし、(b)代替可能なツールあり、(c)参照URL取得不可、(d)生成物はできたが品質未達、のケースを点検する。自動テストの文字一致だけでAIの実動作を検証したと称さない。実生成や独立セッションでの評価をしていなければ未実施と記録する。
- 公開本文の取得を確認してから、[概要欄方針](youtube-description.md)に沿って制作ページへ誘導する。概要欄に長い手順や複数形式の選択を戻さない。更新と検証結果をGitへ残す。
