# VOICEVOX解説動画

普通の解説動画の進行で、窓際族物語の馬鹿らしい出来事を真面目に扱う。2026-10-08に採用された、ずんだもん・四国めたんの静かな掛け合いを既定テンプレにする。ユーザーの指定で話者・曲・演出は変更できる。

## 担当範囲

- このスキル：題材調査、会話台本、VOICEVOX配役・読み、中央の資料設計、BGMと締めの演出方針。
- [remotion-video](../remotion-video/SKILL.md)：React実装、フレーム管理、字幕配置、音声合成、720p書き出し、成果物と監査。動画制作・修正時に併用する。ここへRemotionの共通手順を複製しない。
- この解説経路で新たなWan動画生成は標準にしない。資料として既存動画を利用し、必要な新規映像を頼まれた場合だけ対応スキルへ渡す。スタジオへの公開・登録も依頼時だけ。
- Studio登録を頼まれたら、[madogiwa-studio](../madogiwa-studio/SKILL.md)の「解説動画の音声素材」に従う。生成済みセリフ音声は登録を省き、実際に使った声質参照と音声生成設定を引き渡す。

## 台本はまずチャットで練る

1. ユーザーの叩きと、`01_WORLD/WORLD_BIBLE.md`、`01_WORLD/STORY_TIMELINE.md`、該当エピソードの台本・採用記録を照合する。古い冒頭の状態記録より後段の採用更新を確認。原作漫画と動画の話数、制作順と物語内時系列を混同しない。
2. 構成と会話をチャットで提示し、フィードバックをそこへ反映する。台本検討だけの依頼で音声生成・動画化まで勝手に進めない。「一旦動画化して」は初稿のまま制作する指示として扱う。
3. 編集HTMLは最終調整フェーズだけに使う。途中で毎回HTMLを更新したり、ユーザーを編集ツールへ誘導しない。必要になったら `tools/scenario-editor/index.html` とそのREADMEを使い、全体方針・話者・セリフ・画面指示・修正メモを渡す。原稿と音声用の読み、字幕改行を分ける。
4. 尺を10分へ水増ししない。最大10分程度が当初の想定だが、題材の密度を優先し、尺は音声生成後に実測する。

### 二人の掛け合い

- めたん：事実を落ち着いて解説する。異常な状況でも真顔で、時々フォローになっていないひどいフォローをする。
- ずんだもん：視聴者目線の疑問とリアクション。時々、会社・業務・備品・人物の行動へ辛辣に突っ込む。全発話を毒舌にせず、事実が伝わる間を残す。
- 相手の説明をただ言い換えるツッコミの連続は避ける。新しい事実で疑問が増える会話にする。オチを解説しすぎない。
- 採用された温度感の例：
  - 「よーたんって何者なのだ？」→「アクシデンチュアのCTOよ」→「めちゃくちゃ偉い人だったのだ」→「でも、窓際族よ」→「どういうことなのだ……」
  - 「入社初日からビール飲んでるとか、頭おかしいのだ」→「でも、椅子にはちゃんと座っているわ」→「社会人の合格ラインが低すぎるのだ」
  - キットを見て「資源ごみかと思ったのだ」
- これらは口調の例であり、新作に同じネタや台詞を強制しない。新規の人物名は福ギュン、会社・小道具の表記は正本に従う。

## 画面は簡素、中央は内容に合わせる

基本は無地に近い背景、左右の立ち絵、下部の話者別セリフ。坂本アヒル式ずんだもんを左で左右反転、めたんを右に置き、中央を向き合わせる。口パク・まばたき・表情差分にも同じ反転を適用する。

常設の番組帯、カード枠、名前ラベル、章見出し、進行バー、装飾グリッドは既定では付けない。中央の説明に必要な短い見出し・注釈は使える。

中央は画像専用枠にしない。発話ごとに次を選ぶ：

- テーマ・結論：短いスライド。
- 比較・変化・構造：図解、画像入りスライド。
- 人物紹介：正典の顔写真・キャラクター画像。話している人物の顔が見えること。作業する手の写真だけで人物紹介を済ませない。
- 商品・備品・原作の事実：該当する実物・採用素材。椅子の名前、ジョッキ、キットの材料など、話題の対象が分かる画角にする。
- 過去動画：短く流して、ひと言リアクションして戻る。原音を見せる間は二人の解説を止め、BGMを下げる。

同じ章の画像を機械的に使い回さない。一つの発話でも対象が変わるなら素材を切り替える。公式商品の画像は出典を記録・表示し、生成した架空画像で実物を説明しない。元ネタや過去動画の切り出しは実画像を確認して選ぶ。

## 音と終わり方

寝落ち用にも流せるよう、急な音量増加を避ける。明るい曲でも薄く敷く。

- 導入：昼下がり気分／KK。
- 本編：ほのぼのワルツ【リコーダー】／エクシエ。別版と混同しない。
- エンディング：TheFatRat - Unity。曲の変化で「そろそろ終わり」を知らせ、二人が締めの会話をする。
- エンディングを盛り上げるために音量を上げない。会話後・クレジットでも音量を持ち上げず、静かにフェードアウトする。
- 採用ミックスの数値、取得元、VOICEVOX設定は、制作時に[実装への引き渡し](references/production-handoff.md)を読む。数値だけで聴感を合格と判断しない。

## 実装への引き渡しと確認

動画化するときは、改稿済みセリフ・話者・読み、発話ごとの中央素材、資料動画の範囲と原音の扱い、BGM切替・終わり方を確定できる形にし、[remotion-video](../remotion-video/SKILL.md)へ渡す。既存の制作許可に加えて承認を取り直す必要はない。

完成版は、全種類の中央レイアウトとクリップを実フレームで確認する。特に人物の顔、台詞が指す物体、価格・付属品、写真の切れを点検。「すべての画面が出た」だけで内容の一致を合格にしない。聴感を確認できない場合は、機械的な音声検証と分けて明記する。

改修では必要な範囲だけ再生成する。音量変更だけならRemotionの映像を再レンダーせず、音声を再ミックスして映像をstream copyする。締めの検討には短いエンディング抜粋も添える。
