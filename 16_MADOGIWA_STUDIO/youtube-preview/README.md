# YouTubeのみで配信するローカル検証

起動（16_MADOGIWA_STUDIO から）:

```sh
npx vite --config youtube-preview/vite.config.ts
```

http://127.0.0.1:4176/ を開く。上部の検証用リンクで各画面へ移動できる。

## 検証条件と範囲

本番と同じJournal、EpisodePage、ClipsPage、ClipPage、MovieCard、WorkEditorを使用する。データ取得だけをローカルfixtureへ置き換える。動画本体は公開済みのYouTube2本を使い、サムネイルもYouTubeから取得する。

Viteミドルウェアで `/media/*`、拡張子mp4/webm/mov、管理動画プレビューのバイナリURLを410にする。R2の動画プロキシは撤去。`/__video-audit` に遮断対象へのリクエストを記録する。管理APIは405で遮断し、本番への保存はできない。入力画像・参照音声・資料の公開URLは制作記録として引き続き読み込む。

fixtureは本番DBの完全コピーではない。切り抜きはアップロード済みヨータンの冒頭10秒という検証用データであり、既存切り抜きへの誤ったID割当はしない。既存動画全件のYouTube移行やD1への保存はまだ行っていない。

上記操作後の `GET /__video-audit` は `[]`。Cloudflare動画URLへの要求は発生しなかった。通常・検証用TypeScript、変更ファイルESLint、検証版ビルドが成功。ビルドにはプレビューが全画面を一括importするためのチャンクサイズ警告がある。

公開サイトの `<video>` 使用箇所を全件検索し、Journal、DeferredVideo、MovieCard、切り抜きプレーヤー／本編、管理プレビューを対応。漫画・ギャラリーは動画プレーヤーを持たない。全キャラクター・全テーマ・全動画の組合せを総当たりしたものではない。スマホ実機Safari、YouTubeの広告・地域制限などは未検証。

## 採用方針（ユーザー確認済み）

- 完成動画の本体はYouTube。CloudflareにはID、作品・生成バージョンとの関連、タイトル、公開状態などのメタデータを持たせる。
- 制作記録・プロンプト・入力素材は引き続きCloudflareで保持する。
- 最新版だけをYouTubeへ登録する運用を想定。過去版の制作記録は動画本体と独立して保持する。
- MP4ダウンロード・動画ファイル共有は廃止。サイトの切り抜きActionsからファイル取得処理と保存ボタンを撤去し、ページURL／YouTubeリンク共有に統一した。
- YouTube動画ではYouTube標準の再生・シーク・音量・速度・全画面UIを使う。独自MP4コントロールは表示しない。

## 本番移行で残る作業

1. 保存スキーマを確定する。現行 `videos.r2_key` はNOT NULLで、単にIDを追加するだけでは「動画ファイルなし」の登録経路にならない。YouTube公開動画の関連テーブルを設けるか、保存元を区別してR2項目をnullable化する。空のダミーR2キーで回避しない。
2. 公開データ取得（public-repository、catalog、public-data.server）、管理API・MCPにYouTube ID登録を追加する。検証で追加した任意フィールドは現行DBからはまだ返らない。
3. 最新版の公開動画と制作履歴を独立させる。現行public-data.serverは動画のある生成だけ返すため、公開してよい制作記録を明示して返す設計にする。非公開プロンプトを一律に公開しない。
4. 動画一覧・検索・人物別・代表動画・イチオシ・キャッシュ更新・SEO・サイトマップを実際の保存データで統合テストする。今回の一覧はfixtureであり、サーバー側の絞り込み・ページングの検証ではない。
5. 既存作品と切り抜き本編のYouTube ID対応を確定する。最新版を再アップロードする場合は新IDと切り抜き時間の対応を更新する。区間再生は独立したMP4切り抜きの完全再現ではなく、YouTubeプレーヤーの開始／終了秒指定。
6. 本番のCSP等とモバイル実機を確認し、全画面移行後に旧動画配信・ダウンロードAPIを廃止する。R2動画の削除は今回行っていない。

ローカル検証のみ。本番DB・R2・公開サイトへの反映なし。

## テーマ別トップ画像の配置

`/?covers=1` は既存の固定エピソード3作品のサムネイルを使う配置確認専用モード（動画再生は対象外）。テーマを切り替えて確認できる。酒場・地下労働は854:480、Excelは832:480。スマホでも同じ比率とcontain表示を維持し、切り抜き・ホバー拡大を行わない。通常のYouTube検証モードの代替作品は16:9で表示する。
