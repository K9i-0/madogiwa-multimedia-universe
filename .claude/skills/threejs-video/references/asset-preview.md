# Three.jsモデルの回転・動作・装備プレビュー

2026-10-14の制作知見。モデルを見せるだけの短い動画と、任意時刻を調べる操作ページを同じ入力から作るときに読む。芝居動画の配役・音声生成は必要な場合だけ加える。

## 入力と評価器を揃える

入力GLB、骨・クリップ一覧、装備設定、表示尺度とハッシュをmanifestへ残す。制作中の仮モデルを最終版と取り違えないよう、装備の接触調整と最終動画の入力が同じ版であることを確認する。

姿勢を評価する処理はブラウザとRemotionで共用する。時刻を壁時計や前フレームの加算から作らず、`frame / fps` から直接決める。クリップ切替やシーク時は初期姿勢を復元し、選択中のクリップを評価してから、装備中だけ握りなどの上書きを行う。

そのモデルに存在する骨・クリップ・アンカーを読み、必須のものがなければ表示前に理由を返す。クリップ名をファイル名から推測しない。複製リグを使うときも、別表示のmixerや骨へ状態が漏れないよう確認する。装備の行列と指姿勢は [手持ち小道具の装備](../../humanoid-motion/references/prop-attachment.md) を参照する。

## 見せるカットを選ぶ

| 見たいもの | カット・操作 |
|---|---|
| シルエット、顔、背面構造 | 全身の回転。フード、髪、足先が切れない画角 |
| 肩・袖・脚の変形 | 代表動作の始点・中間・保持・終点と連続再生 |
| 握り、道具の向き、接触 | 装備専用ポーズの全身と手元、反対側や背面 |
| 状態切替の不具合 | クリップ選択、再生・停止、シーク、装備ON/OFF、必要なら骨表示 |

全動作を短い動画へ均等に詰める必要はない。動画は目的の違う代表例を選び、操作ページで残りを確認できるようにする。固定ポーズの保持時間を「動くモーションの尺」と混同しない。

画角は変形後の頂点と道具の位置で確かめる。静止時のboundsだけでは、挙手・キック・長いレンズやストラップの見切れを判定できない。寄りカットで下半身を切る場合は意図したクロップとして明記し、全身が収まった検証とは分ける。長い小道具があるときは人物の中心だけでフレーミングしない。

## 形式・機能・見た目を分けて検査する

- **形式**：型検査、必要ファイルと埋め込みテクスチャ、骨・クリップ・アンカー、有限な値、最終入力ハッシュ。
- **機能**：複数クリップと複数位相を順不同で評価し、同じ時刻へ戻ると骨行列・装備位置が一致すること。装備ON→OFF後に、独立した未装備サンプルと一致すること。
- **見た目**：静止画と連続再生で顔・袖・指・接地・背面・道具との干渉を確認する。固定ポーズの接触調整を全クリップの衝突回避保証へ拡大しない。
- **動画**：尺・fps・解像度・フレーム数、音声の有無、終端までのデコード、カット境界と代表画像。完成MP4で字幕・ラベルの可読性も見る。

全フレームを数値走査する場合も、画角検査は接触・変形の合格を意味しない。画素数などの検出は既知の失敗を見つける補助で、別の壊れ方まで保証しない。

## デコード成功でも、撮影された画が壊れる場合

一例では、Three.jsをRemotionでPNG入力・並列2でレンダーした動画に、頭部の帯が繰り返される描画崩れが出た。動画ファイルのデコードは正常だったため、ffmpegの終了コードだけでは発見できなかった。JPEG入力・quality95・並列1へ変えた条件で解消したが、原因の一般化や他環境での成功保証はしていない。

似た症状では、短い再現区間で `--image-format=jpeg --jpeg-quality=95 --concurrency=1` を候補として比較する。すべての動画を常にこの設定へ固定しない。CLIの対応引数は使用中バージョンで確認し、採用した条件を記録する。

再レンダー後は最終MP4から画像を抽出し、元症状が消えたかを見る。プレビュー用stillが綺麗でも、完成動画が同じとは限らない。上記の例では衣服の色が一定量映ることを全フレームで検査したが、衣装や画角を変えたら同じ閾値を流用できない。

## 文字と成果物

寄りカットでは、全身カットで余白にあった説明文字が服へ重なることがある。文字サイズを小さくする前に、短い文言・配置・背景板のコントラストを調整する。カット境界、最も明るい背景、手や道具に近いフレームを完成解像度で確認する。

完成動画の解像度・音声・保存場所は [remotion-video](../../remotion-video/SKILL.md) に従う。再現するコード、入力の参照とハッシュ、依存lockfile、検証記録を追跡し、中間動画やキャッシュは追跡しない。単なるプレビュー依頼でゲーム本編の採用モデルや動作を切り替えない。

PRへ動画を添付する依頼では、使用中の `gh pr edit --help` で `--attach` の対応を確認する。対応版なら本文ファイルと添付を使い、既存の本文・添付を保持する。更新後にbase、head、添付URLを読み戻し、アップロード成功と差分反映を確認する。添付はモデルの制作やローカル表示自体に必須ではない。
