## 視聴者と構成

採用作の視聴者は、Codex／Claude CodeでWebサイトやアプリを作るアマチュア開発者。モデル名はなんとなく知っているが、動画・音声生成まで詳しいとは限らない。新作では題材に合わせて前提知識を明示する。職業エンジニアだけに狭めない。

初心者が追える本筋に、詳しい人にも新しい実践知を織り込む。実際の制作記録、失敗と修正、入力の工夫、部分修復、費用の内訳などを使い、架空の経験を足さない。

構成の出発点は「作れるものと動機 → 今回の範囲と全体像 → 役割・仕組み → 実例と工夫 → 短いまとめ」。全作品へ同じ章数や費用パートを強制しない。

- 冒頭はBGMを少し先行させ、会話に関連する完成例を無音で見せる。説明なしに大音量の動画だけを流さない。
- 「自分も作りたい」「難しそう」を会話にして、視聴者の普段の作業との接点を作る。短い自己紹介と今回分かることを早めに伝える。
- 採用作の導線は「アホやな〜 → ワイも作りたい → いつものCodexか → バイブコーディングの冗談 → 自己紹介 → 今回の紹介 → ちなみにワイ、動画編集ソフトとか…」。順序と自然な接続を参考にし、同じ冗談を毎回使わない。「本当に要らないと思われてるんじゃ」の冗談はそこで切り上げる。
- 特定の手法を唯一の方法として紹介しない。GUIサービスも選択肢と認め、今回は何を扱う動画かを示す。
- 初出の制作リポジトリなどは、リンクや詳説を後で出すならそう予告する。公開URLと概要欄は実際の対象へ更新する。
- 終盤は短く締める。次回予告で別技術の説明を始めない。クレジットは概要欄、会話後は余韻とフェード。

## 配役を差し替える

継承するのは「試したい人の疑問・反応」と「手法を説明する人」の会話構造。やめ太郎＆たこさんに固定しない。たこさんの代わりにそば屋が説明してもよく、知識や役割も台本に合わせる。

制作開始時に、役割／キャラクターID・表示名／左右位置／正典立ち絵と表情／音声方式・参照音声・設定／字幕色／クレジットを作品側へ記録する。`02_CHARACTERS/VOICE_CAST.md` と各キャラクターの人物同一性を参照し、別キャラへたこさんの声を流用しない。

採用作はやめ太郎がIrodori、たこさんがVOICEVOX中国うさぎ・ノーマル（61）、速度1.1、音高0。スキル名がVOICEVOXでも全員をVOICEVOX化しない。そば屋への変更時はそば屋の正典声と素材を使い、旧名・旧字幕色・旧クレジット・口パク参照が残らないよう確認する。

既存の立ち絵差分を意味に合わせて使う。説明の通常顔だけでなく、喜び、驚き、心配、呆れなどを聞き手にも割り当てる。全発話で機械的に表情を変えない。口開閉とまばたきは同じ表情・同じ足元位置を保ち、切替で体が跳ねないようにする。

## 掛け合いを音で成立させる

- 疑問 → 短い説明と具体例 → 反応や次の疑問で進める。相手の説明の言い換えだけで台詞を増やさない。
- 説明役も会話に参加し、長文の講義を聞き手の相づちで区切るだけにしない。冗談は内容の理解を助ける位置へ置き、オチを説明しない。
- 普段の口調と聞きやすい短い息継ぎを優先する。韻は自然に成立する箇所だけ。「期待したい、でも課金は控えたい」のような韻のための不自然な文や、対応関係が分からない例えを避ける。
- 原稿、音声用の読み、字幕を分ける。VOICEVOXの生成・共通読み辞書は [voicevox-control](../../voicevox-control/SKILL.md) を使い、数字・固有名詞・「方」の文脈を確認する。採用作のWan 3.0は「ワン サンテンゼロ」。表記まで読み仮名に置換しない。
- モデルと操作ツールを混同しない。採用作の三役は「指示を考えるモデル」「映像を作るモデル」「声を作るモデル」。必要な用語から順に説明する。
- 実践知は手順に結びつける。スキル・キャラクターシート・制作記録をGitで育てる話も、失敗を次回減らす具体例として入れる。
- 価格は日本円を主に、基準日・換算条件・通常料金と割引・試行回数を区別する。採用作の平均約300円などは当時の実績であり、新作へ無検証でコピーしない。

## Excel風の画面

白いワークシート、濃緑のタイトルバー、列・行見出し、数式バーを思わせる章名、下部のシートタブを基本にする。中央に資料、左右に立ち絵、下部に字幕。操作できない動画なので、実際の操作説明と誤認する不要なボタンや細かなUIを増やさない。

v12の1280×720ではタイトルバー36px、章名33px、列見出し25px、左行番号34px、下部タブ35px。中央資料の元枠は幅760pxを0.9倍、字幕は左右245px・下42px・文字29pxを出発点にしている。これは採用例の値であり、配役や資料の幅に合わせて調整する。

- 地は白、本文は濃い色。採用色は本文 `#182F24`、緑 `#176B47`、補助文字 `#485C50`。薄緑地に緑の細字で説明を詰めない。
- 話す内容を画面にも全文転記しない。資料は関係、比較、手順、数値、実物を見せ、字幕と役割を分ける。自己紹介の画面は名前で十分。「どうも」を見出しにしない。
- 表は連続したセル、角の立った枠、選択セルの緑枠と小さなハンドルで統一する。全場面を表に押し込まず、写真・実動画・図も使う。
- 複雑な図や役割表は、今話している行・セル・矢印だけを強調する。章単位で固定せず、発話内の該当句の時刻に合わせる。次の説明を先に強調しない。
- 下部タブは実際の章名・章順へ更新する。装飾グリッドは薄くし、文字や映像の下は白地などで読みやすさを確保する。
- 同じ動画・画像を参照中は字幕変更で再マウント、再生位置のリセット、フェードの再実行をしない。メディアの継続時間と字幕ページを別管理する。
- 冒頭例は無音で会話を優先。原音を聞かせる実例では解説を止めBGMを下げる。短いニュースなどを最後まで見せる指定があれば、字幕の都合で打ち切らない。

## 制作・確認と育て方

実装・レンダーは [remotion-video](../../remotion-video/SKILL.md) に従う。音声の実測から字幕・強調・クリップ・章を合わせる。再利用元の固定フレームを新台詞へそのまま当てない。

完成MP4で導入、各レイアウト、強調の移動、字幕改ページ、表情切替、実例動画への出入り、締めを確認する。720p実寸で字の大きさ・コントラスト・重なりを確認し、静止画だけでチラつきを合格にしない。読み、会話の間、BGMとの関係も検証する。聴感を確認できなかった場合は機械検査と区別して報告する。

次作で採用された改善は、作品の採用記録を残してからこの資料の該当項目へ反映する。汎用化できる画面・会話の工夫と、作品固有のネタ・配役・価格を区別する。ネタ系の別フォーマットが育った場合も、技術解説の既定を上書きせず別の参照先として整理する。
