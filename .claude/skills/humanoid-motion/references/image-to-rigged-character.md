# 参照画像から、動かせる人型モデルへ

2026-10-14の制作で確認した判断を整理した参照資料。非ボクセルの人物と着脱する小道具を、画像入力から生成・仕上げ・リグ・装備へ進める場合に読む。特定作品の素材や生成設定はこの手順の依存物にしない。

## 最初に、何を一体で作るか決める

顔・髪・衣服・身体は人物同一性を確認できる全身入力にまとめる。持ち替えるカメラや道具は別生成が向く。指と道具が一体化すると、装備を外す・別ポーズで持つ調整が難しくなる。着脱しない装飾まで一律に分離する必要はない。

人物には空の両手、腕と胴の隙間、指の分離、全身が収まる姿勢を用意する。道具は正面・背面・側面で機能的な形と左右差を確かめる。長いレンズ、持ち手、三脚座など、何がどこへ付くかを入力時点で区別する。

## シートは背面の構造まで指定する

- 正面だけでなく、側面と背面でも髪・服の構造が続いているか確認する。フードなら、下ろした状態、開口部、縁の厚み、背中へ垂れる位置まで見せる。
- 読める必要のある衣服の文字は、全身シートと別に綴りの参照を用意すると補いやすい。文字参照の背景矩形を服の模様として採用しない。印字の大きさ・位置・紐による遮蔽は人物シートを優先する。
- 製品形状を参考に架空の表示へ替える依頼では、形と文字の要件を別々に記録する。指定されたロゴだけを置き換え、形まで無断で一般化しない。
- 生成シートの各面は校正された投影ではない。身長・体格・姿勢・左右の飾り・指の向きが揃っているか、画像として検査する。

## 回転動画を四面図に使う

Wanで生成する部分は [wan-video](../../wan-video/SKILL.md) に従う。動画は四面図を得るための中間入力で、動画そのものを静止画入力APIへ送るわけではない。

固定カメラ、一定の全身サイズ、1体だけの回転、背景・照明の安定、低いモーションブラーを指定する。シートの複数パネルをそのまま映像へ並べない。頭・胴・足の同時回転と、開始・一周後の向きを明示する。

8秒の依頼でも、一周せず約半周で止まった例がある。尺は回転角の証明にならない。正面・左右・背面は予定秒数から決めず、実フレームの角度を見て選ぶ。抽出時に方向ごとに別々の尺度へ拡大しない。フードの消失・平坦化、背面への胸文字の混入、腕や足の動きも途中を含めて確認する。

片側だけ足りない場合は、再生成と画像補完を比較する。左右差が小さく、ユーザーの意図に合うなら、採用した前・側・背面を参照したImagegen補完が候補になる（Claude Code等では`codex-imagegen`スキル経由）。左右非対称の衣服、機材、文字、指を単純な鏡像で済ませない。補完面は推定画像であることを残し、元動画から抽出した面と区別する。

採用画像とプロンプト、実行設定、抽出時刻、補完の来歴を追跡する。8秒、1080P、縦長などは案件の選択であり共通の必須設定にしない。生成解像度はユーザー指定とリポジトリの既定を守り、最終動画の解像度から引き上げない。

## 生成結果を完成品にする

Tripoの接続・送信・重複実行対策は [tools/TRIPO.md](../../../../tools/TRIPO.md)、複数画像の処理は既存の `tools/tripo_multiview.py` を確認する。過去のモデルID・面数・クレジット実績は次回の仕様や価格の保証にしない。原型、実際の入力、task ID、取得ハッシュ、採用条件を対応させる。

| 目立つ差 | 切り分けと仕上げ |
|---|---|
| 服や髪が金属的に見える | 形を削る前にmetallic・roughness・normalと照明を確認する。全アセットを一律の材質値へ変えない |
| 胸文字や製品名が崩れる | 綴りを指定した参照と照合し、局所テクスチャ修復やデカール・薄い文字メッシュを選ぶ。元の文字片が外へ残らないか近接で見る |
| 長い鏡胴や持ち手が短い | 基準寸法を一つ決め、全体尺度と局所比率を分ける。人物の指に合わせるために道具全体を潰さない |
| 隙間、癒着、開口部がある | 生成メッシュの欠陥と意図された服の重なりを区別する。全穴を閉じることを無条件の目標にしない |

薄い文字メッシュは綴りを確実にできるが、近接では名板に見えることがある。採用画角で必要な質感に合わせる。見えない旧文字を覆っただけで、テクスチャ全体が修復されたと報告しない。

局所変形では元データを残し、対象範囲・基準軸・倍率を記録する。幅を実寸へ合わせても、奥行きや全周形状までCAD精度になったことにはならない。全身・正面・背面・両側面・文字の近接を、書き出したGLBの再読込で確認する。

## リグは、骨名の一致と見た目を別に見る

### リグのない生成メッシュから始める場合

1. 採用した静的モデル、互換にしたい動作の入力GLB、必要な指骨とsocketを決める。作業は新しい派生ディレクトリの`build.py`等へ分け、元モデルへ上書きしない。
2. 初回の骨作成・指と身体のウェイト付けは [福ギュンv3のbuild.py](../../../../04_GAME_ASSETS/3d/characters/fukuchan/rig_v3_20260917/build.py) と [制作記録](../../../../04_GAME_ASSETS/3d/characters/fukuchan/rig_v3_20260917/README.md) が実装例になる。キャラ固有の入力、関節座標、部位判定、首の材質補修を含むため、そのまま新モデルへ実行しない。入力・出力、関節の目印、指の軸、衣服の部位分けを対象モデルに合わせ、不要な補修は引き継がない。
3. 採用動作の名前・階層・出典を保持しつつ、対象メッシュに骨を配置し、初期ウェイトを付ける。[retarget.py](../../../../04_GAME_ASSETS/3d/characters/fukuchan/rig_v3_20260917/retarget.py) は元姿勢・四肢方向・脚長を考慮する実装例。骨数や座標をコピーするのではなく、まず腕・指・脚の代表姿勢で変形を確認してから全対象クリップへ進む。

既存モーションを使う場合は [リターゲットと本編採用](retarget-and-adopt.md) と、体型ごとの元姿勢を確認する。顔・髪・衣服など採用済みの形状を保つ範囲を先に決め、骨の位置・長さ・軸とウェイトを調整する。同名の骨があるだけでローカル回転のコピーが成立するとは限らない。

- 腕に近い胴やフードへウェイトが漏れると、骨は正しくても袖が引っ張られる。直線距離だけでなく表面のつながり、非連結部位、UV境界の同位置頂点を調べる。
- 頭・髪と、首に近いフードの追従を分けて見る。近い頂点へ一律の影響を与えて衣服を頭へ引かせない。
- 手首の一点でねじる前に、前腕の軸回りの回転と親指方向を確認する。甲・掌は近接画像でも確認する。
- 骨数、ウェイト正規化、元頂点・UV・材質の保持と、上げ始め・保持・下ろす途中の自然さをそれぞれ検査する。

元モデルを保った新しい固定ポーズや小道具装備の追加は [手持ち小道具の装備](prop-attachment.md) へ進む。特定の骨数やクリップ数を別のモデルへ強制しない。

## 成果の見せ方

回転だけで形状、代表動作で変形、装備の寄りで握りと干渉を見せると、確認対象を分けやすい。動画と操作ページで共通の姿勢評価を使う手順は [Three.jsのアセットプレビュー](../../threejs-video/references/asset-preview.md) を参照する。

検証記録には入力・最終GLB・装備設定・動画のハッシュと、数値で確認したこと、実画像で確認したこと、未対応のことを分けて残す。生成元の静止画が良いこと、骨が動くこと、書き出しが成功することは、それぞれ別の段階の成果である。
