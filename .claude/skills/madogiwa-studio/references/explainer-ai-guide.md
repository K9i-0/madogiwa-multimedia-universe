# 技術解説のAI向け資料

2026-10-22更新：主操作は「AIへの指示をコピー」1つ。実行指示書（workflow.md）と動画内容の記録（guide.md）を分離し、動画資料から実行指示書へリンクする。実行指示書は依頼文と全文をコピーし、具体的な公開コード・資料へのURL、読む順番、必要入力、必須工程、代替可能な条件、不足時の停止と再開方法、品質確認を含める。Tripo回ではTripo生成を必須とし、回転動画モデルは要件を満たすものを選べる。必須ツール不足を理由に別方式へ独断で変更させない。用途も勝手に追加しない。視聴者が動画で話した内容をAIへ渡し、自分の制作を相談できる資料を、採用動画とセットで用意する。ネタ系解説へ一律に適用しない。

## 内容の作り方

- 採用台本と画面内の説明・プロンプトを参照し、要点、実践手順、注意点、依頼例、動画で話した内容、出典・必要な補足をまとめる。制作内部の指示書をそのまま公開資料にしない。
- 動画URL、制作ページURL、対象版、動画制作日・資料更新日を記載する。台本由来の発話は「採用台本より」と示し、自動書き起こしと称さない。
- 画面にだけ出したプロンプト例も収録する。資料用に新たに書いた依頼例と、実際に動画で紹介したプロンプトを区別する。
- 料金、割引、モデル、設定、販売状況は動画制作時点の説明として扱い、現在の仕様と混同させない。実績と試算、用途別の設定差も保つ。
- 概要欄から外す詳しい制作説明や参考リンクは、必要なものをここへ移す。未採用素材、非公開メモ、認証情報は含めない。
- URLを読めないAIにはMarkdown全文を貼る方法を案内する。資料だけで参照画像・API設定まで揃うと説明しない。

## 既存実装への追加

以下はリポジトリルート基準。新しい仕組みを重複して作らず、現在の実装を確認して追加する。

- 資料正本：`16_MADOGIWA_STUDIO/src/content/explainers/<slug>.md`
- 対象slugと採用YouTube ID：`src/lib/explainer-catalog.ts`
- Markdownの登録：`src/server/explainer-guides.ts`
- 制作ページ：`https://madogiwa.work/episodes/<slug>`
- AI用Markdown：`https://madogiwa.work/episodes/<slug>/guide.md`

`src/`の略記は `16_MADOGIWA_STUDIO/` 基準。Tripo、Wan 3.0、LINEスタンプの3資料を構成の例にできるが、題材や固有設定を複製しない。

資料は対応する公開中の動画に紐づけ、制作ノートの `productionNotes` とは独立させる。資料を出すためだけに非公開の制作ノートを有効にしない。動画差し替え時は対象版とYouTube IDを更新する。通常ページの初期HTMLに本文を含め、AI用URLはJavaScript・認証不要の `text/markdown` を返す既存構成を維持する。

## 公開と確認

動画制作の段階で資料を準備し、依頼済みの公開・Studio登録の範囲で掲載する。台本相談だけの依頼を公開依頼へ拡張しない。

1. 対応動画の公開状態・ID・slugと資料の対象版を確認する。
2. 制作ページの資料、1つのコピー操作（依頼文＋実行指示書全文）、実行指示書と動画資料の分離、Markdown取得、スマホ表示を確認する。コピー拒否時の手動コピー欄も維持する。
3. 公開していない動画・未登録資料のMarkdownが取得できないことを確認する。初期HTMLとMarkdownが同じ採用資料を参照することを確かめる。
4. 公開ページとMarkdown本文の取得を確認してから、[概要欄方針](youtube-description.md)に沿って対応動画の概要欄へ制作ページリンクを載せる。HTTP取得成功と個々のAIのURL閲覧対応は区別し、特定ツールで読めない場合は明記する。
5. 資料・公開対応・概要欄の更新記録をGitへ残す。
