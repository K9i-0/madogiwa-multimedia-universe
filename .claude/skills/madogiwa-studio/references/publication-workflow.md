# 動画の登録・公開の共通手順

2026-10-31ユーザー指定。YouTube、公式サイト、Studioのいずれかへ動画の登録・投稿・公開を頼まれたら、以下を標準として追加の説明・選択質問・公開確認なしで実施する。制作だけの依頼や「投稿準備だけ」は公開許可にしない。予約、Shortsのみ、横版のみ、非公開、サイト掲載なし等の明示指示は該当項目を上書きする。過去作品の一括変更はしない。

## 標準の成果物

- YouTubeへの公開と公式サイトへの掲載をセットで完了する。
- 採用本編が約1分30秒までなら、全編を保った縦Shortsも作り、本編と基本同時投稿する。90秒前後の数フレーム・音声余白の差は一律除外の理由にしない。既に縦のShorts適合動画なら同じ動画を重複投稿せず、1本で満たす。
- Shorts編集は[shorts-video](../../shorts-video/SKILL.md)を使う。短編全編の変換で切り出し候補を質問しない。長編からの切り出しは同スキルの候補相談を維持する。
- Wan、MiniMax H3、Seedance等の動画生成AIを使った作品は、使用モデル・本番プロンプト・採用入力素材・生成設定を登録した制作ページを必ず公開する。`productionNotes:true`と対象`generationId`を指定する。生成AI以外も公式サイトの作品ページを掲載し、実在する制作資料のみ載せる。
- Shortsは同じ作品の派生版。本編の公式サイトページへ導線を集約し、Shorts用の別エピソードを作らず、本編IDも置換しない。Shortsのみの明示依頼では新しい横版を作らず、サイト登録の扱いもその依頼範囲に従う。

## 公開までの順序

1. ローカルのupload記録・hash、Studio一覧、YouTubeの既存IDを確認する。既存IDは再利用し、公開済み本編があれば再投稿しない。
2. 本編と必要なShortsの書き出し・字幕・音声・メタデータを先に揃える。同時投稿とは同じ作業内で連続公開すること。秒単位の同時刻は保証せず、同時化のために未指定の予約日時を設定しない。
3. 既存作品を取得するか新規エピソードを作り、v1のgenerationIdを取得する。制作情報・実際のプロンプト・採用画像/声質参照/編集資料を登録する。入力はPUT後のreadyまで確認する。アップロードURLをメモリに保持して同じチケットを再試行し、単なる転送失敗で新しい入力行を重複作成しない。URLや認証情報はログ・ファイルに保存しない。
4. 本編をYouTubeへpublicでアップロードし、返ったIDを直ちにStudioへ登録する。既存公開IDならそのIDを登録する。生成AI作品は制作ノートを有効にし、同期後にready・is_active=1・公開ページのタイトル/動画/制作情報を確認する。
5. 公開を確認できた作品の制作ページURLを本編とShortsの概要欄へ必ず入れる。初回にまだページが公開されていなければ、本編の初回アップロード後に同じ作業内で説明文を更新する。トップページURLで代用しない。Shortsには現行本編URLも入れる。
6. Shortsを続けて公開する。両動画の概要欄・タグ・公開状態・processing succeeded・公式チャンネルを再取得し、サイトのリンク先も照合する。更新直後に旧値が返る場合は短く待って再取得し、無制限の再送や別IDの投稿をしない。
7. ローカルmetadata/descriptionと公開内容を揃え、動画ID、サイトURL、generationId、入力assetId、確認結果を登録記録へ保存する。最終報告は本編・Shorts・制作ページのリンクを簡潔に示す。

## 完了条件

本編のYouTube公開・処理完了、公式サイト掲載、必要なShorts公開・処理完了、両概要欄の制作ページリンク・必要クレジット・タグ、生成AI作品の制作ノートと採用入力readyが揃って完了。処理待ちや失敗は項目とIDを明示し、成功済み部分を再投稿せず残りを再開する。

概要欄の正本は[youtube-description.md](youtube-description.md)。予約は明示依頼時だけ[mcp-tools.md](mcp-tools.md)の予約手順を使う。予約中はサイトのwaiting_publicが想定状態となるため、即時公開へ変更せず、予約日時と処理完了を確認して公開後の掲載確認を残作業に記録する。
