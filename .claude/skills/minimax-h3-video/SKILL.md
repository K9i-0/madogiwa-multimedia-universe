# MiniMax H3動画制作

Macで台本・入力を用意し、Linux NVIDIA CUDA環境でComfyUIのH3を実行する。
同僚の `local-video` / `colab-video` を参考にした独立実装。参照コミットと契約条件は
[setup-and-cost.md](references/setup-and-cost.md)を最初に読む。
**2026-10-27: A100でR2Vの通常20step・Turbo 8stepの480p/768pを実生成済み。**
品質の採否はユーザー判断。音声ストリーム・尺・全編デコードは確認済みだが、音声内容の聴取やリップシンク精度を自動検証済みとは扱わない。

## 投稿・登録への引き継ぎ

YouTube・公式サイトへの登録依頼では[madogiwa-studioの共通手順](../madogiwa-studio/references/publication-workflow.md)を使う。本制作経路は動画生成AI作品のため、実際のモデル・プロンプト・採用入力・設定を持つ制作ページを必ず公開し、本編とShortsの概要欄へリンクを載せる。約90秒までの本編は全編Shortsも作成して基本同時投稿する。制作だけの依頼では公開しない。

## H3の3つの選択肢（2026-10-27ユーザー指定）

H3指定で構成の指定がなければ **480p Turbo** を使う。動画制作全体の標準をWanから変更する指示ではない。

| profile | 生成解像度（横） | 設定 | 30秒の実測生成時間 | 用途の目安 |
|---|---|---|---|---|
| `480p-turbo` **既定** | 864×480 | 純正＋Turbo v1.0、8step | **8分33秒** | 動きの少ない動画・試作・速度優先 |
| `768p-turbo` | 1344×768 | 純正＋Turbo v1.0、8step | **37分50秒** | 解像度と時間のバランス |
| `768p-base` | 1344×768 | 純正、LoRAなし20step | **88分21秒** | Turboの品質が気になる場合の比較候補 |

実測はA100、同じ通販題材、15秒×2章、画像・Irodori音声参照あり。題材・GPU・尺・入力枚数で変動し、品質の順位は保証しない。Singularity V2/v1.3・Hybridは標準選択肢に含めない。
実行前に[profiles.md](references/profiles.md)を読み、固定LoRA・サンプラー・シフトと実測条件を使う。既定変更だけを理由に既存動画を再生成しない。

## 環境と契約

- Apple Siliconだけで動くと案内しない。既存のCUDA環境があれば優先し、今回の3構成の実測を再現するColab実行はA100・1workerを使う。L4の費用・速度は別測定として扱う。
- Google AI Plusは月50 CU。50時間ではない。既存特典の残高と選択可能GPUを先に確認し、追加契約を自動購入しない。
- H3ライセンスの条件は参照資料として案内する。2026-10-26ユーザー指定: 配置地域不明を理由とする独自の保守的な停止条件は撤廃し、動作確認を優先する。配置地域は取得できる場合のみ記録し、不明ならunknownで継続する。
- モデルは約54GB。Driveは入力・結果だけ。重みは実行ディスクに直接DLし、GCSや有料Driveキャッシュを勝手に追加しない。
- Googleの公式Colab CLIも利用可能。利用するなら公式READMEと現在の認証手順を確認する。ブラウザCookie抽出・非公開APIによる認証の代用をしない。

## CLIでの実行（2026-10-26ユーザー希望の標準経路）

ブラウザでのノートブック操作より[cli.md](references/cli.md)の公式Colab CLIを優先する。
`colab_h3.py`で準備・実行・状態確認・回収・停止を行う。初回OAuth認証だけユーザー操作が必要。
2026-10-26、公式CLI経由のL4確保・H3実生成・結果回収・自動停止も確認済み。
ComfyUI APIはGPU内の127.0.0.1で使い、公開トンネルは不要。
同僚の`h3_run.py`はComfyUI API部分の参考になったが、同僚のColab運用自体はブラウザ前提。

## ノートブックでの動作検証（代替経路）

[assets/mmu_h3_smoke.ipynb](assets/mmu_h3_smoke.ipynb)をColabで開く。
自己完結したノートブックで、DriveマウントやAPIキーは不要。
最初のセルはGPUと配置地域の照会だけ。配置地域の照会結果にかかわらず、窓辺のコーヒーの湯気を1本生成する。
設定は864×480、124フレーム（約5.17秒）、24fps、20step、seed 42。
キャラクターや声の再現性の検証は、この配管テスト合格後に別に実施する。

1. 初期CU残高、CU/時、GPU、配置地域を記録。
2. セットアップと推論を分けて計測。重み・ComfyUIは固定revisionを使用。
3. `run_workflow.py`はprompt_idを出力横の`.job.json`へ保存する。同じコマンドでポーリングを再開できる。通信切断を新規生成として再送しない。
4. MP4の解像度・フレーム数・24fps・音声ストリームを自動確認。別途、冒頭・中間・末尾の画と音を確認。
5. 480p原本と720p版、ログ、workflow、実測を回収。回収を確認してランタイムを削除し、CU消費を止める。失敗時もログを回収して終了する。Colabを修正待ちで待機させるのはユーザーが明示したときだけ。
6. 生成成功と画・音の合格を制作記録へ追記してから「検証済み」とする。未生成を成功と扱わない。

## 作品の入力と実行

### H3用のプロンプト設計

**新規プロンプト・改稿では、先に[H3のプロンプトと参照設計](references/prompt-design.md)を読む。** 実行設定だけを決めてWan用本文を流用しない。人物同一性と正典音声は共通だが、Wanの30秒マルチショット規則、API固有の参照形式、全員の口・顎を動かす指示はH3の既定にしない。

- 構図・物体数・大小差がネタの成立条件なら、まずそれを満たす場面参照画像を用意し、正典と照合する。今回のメガジョッキ編では「場面画像1枚＋小さな演技」で改善した。ただしR2Vは始点画像の完全固定ではなく、単一画像が常に最良という比較結果でもない。
- 本文は「参照の役割 → 初期状態 → 必要な動作と発話順 → 終了状態・音響」の順で書く。禁止語の追記だけで直そうとせず、物の所在、手との接触、状態の遷移を整える。
- 静かな会話劇では一つの場所・画角と少数の動作を第一候補にする。ユーザーが求めた受け渡し・飲酒・激しい演技まで削らず、必要なら動作の節目で分割する。
- `<Picture n>` / `<Audio n>`を実際の入力順へ対応させ、各音声の話者と今回の台詞を明記する。音声参照は波形・時刻の完全再現を保証しない。仮面の人物へ通常の口パク指示を一括適用しない。
- 初回から人物・小道具・接触状態・台詞・仮面・白Tを監査できる入力と本文にする。メガジョッキ編v2は白Tの黒点補修を要したが、2026-10-30のBBQ編では白い綿布の状態を具体的に指定し、4カットで補修なしの改善を確認した。白Tの新規本文・修正は[比較結果と採用文面](references/prompt-design.md#白tの点状陰影bbq編の比較)を第一候補にする。採用済みを全条件達成とは扱わず、仮面などは別に監査する。

### 入力の準備

正典キャラクターの人物同一性、実写の顔、`VOICE_CAST.md`の声を維持する。
音声が必要なら既存採用WAVを優先し、新規VOICEVOXは`voicevox-control`、Irodoriは`tools/IRODORI_TTS.md`に従う。
画像生成には`imagegen`を使い、同僚側のDraw Things依存を持ち込まない。

- `t2v`: 画像なし。環境検証向け。人物同一性の検証には使わない。
- `i2v`: 始点・終点画像。`fl2va`モデル。両端が正しくても途中の人物崩れを確認する。
- `r2v`: キャラ参照・音声参照。`ref2va`モデル。画像最大9、音声最大3、合計12。
  `--image`順に`<Picture 1>`、`--audio`順に`<Audio 1>`。参照音声がそのまま波形コピーされるとは保証しない。
- `frames = 17k+5`、24fps。標準124〜362フレーム、短い実験も5以上で指定可能。
- 既定は480p Turbo（横864×480、縦480×864）。768pはユーザーの指定・選択に従い、品質不足を理由に自動で解像度を上げない。
- `--profile`で3構成を選ぶ。省略は`480p-turbo`。R2Vはref2v用、T2V/I2Vはfl2v用のLoRAを使い分ける。TurboはLoRA＋SigmaShift 12/3＋euler/beta/8stepを一体で適用し、単にstep数だけ減らさない。今回のTurbo実生成・品質評価はR2Vであり、他モードまで検証済みと扱わない。

```sh
python3 .claude/skills/minimax-h3-video/scripts/build_workflow.py \
  --mode r2v --profile 480p-turbo --prompt-file 03_SCRIPTS/<run>/ch1_prompt.txt \
  --frames 124 --image character.png --audio dialogue.wav \
  --out 03_SCRIPTS/<run>/ch1_workflow.json
```

参照入力はworkflowと同じディレクトリに実体で置き、フラットなファイル名を指定する。
CUDA機へ必要なworkflow・入力・`setup_cuda.py`・`run_workflow.py`だけを渡す（.envや認証情報を一括zipしない）。

```sh
python3 setup_cuda.py ch1_workflow.json --root /content/mmu-h3 \
  --territory-evidence '確認した実行リージョンと根拠'
python3 run_workflow.py ch1_workflow.runtime.json --out ch1.mp4
```

setupは専用の新規runtime向け。既存ComfyUIはそのサーバーを`run_workflow.py --server`へ渡し、モデルと入力を配置する。
異なる入力や修正版は出力名も変更する。ジョブ記録の削除による盲目的再送を避ける。

## 監査と納品

台本・実プロンプト・入力・設定・実測記録を`03_SCRIPTS/<run>/`へ。
動画・重み・テスト中間物はGitへ入れない。ゲーム採用動画だけ既存の正典規則に従う。
声の変更・二重発話・別のキャラの口が動く・途中の顔/身体変化を確認する。
物体の個数・大きさ・手との接触、仮面の装着と発話中の変形、白Tの局所的な点状陰影も確認する。画像・プロンプト・動作・seedを同時に変えた比較から単独の改善原因を断定しない。修正判断と今回の実例は[プロンプト設計の監査](references/prompt-design.md#生成後の判定と改稿)を使う。
字幕と仕上げは`remotion-video`へ委ね、480pから720pへ通常リサイズを一度だけ行う。768p素材は原寸を維持する。
864:480は厳密な16:9ではないため、1280×720への仕上げは縦横比を維持して微小余白を足す。

スクリプト変更後は`build_smoke_notebook.py`で埋め込みコードを再生成する。
